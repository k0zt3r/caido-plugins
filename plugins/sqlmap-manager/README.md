# SQLmap Manager — локальный Caido plugin

Импортируй `dist/plugin_package.zip` через Plugins → Install. Появится SQLmap Manager в боковом меню и пункт Send to SQLmap Manager в контекстном меню запроса. Меню только выбирает запрос; процесс запускается кнопкой «Запустить».

Это самостоятельный frontend/backend plugin. Shell workflow и отдельный API-сервис не нужны. Короткий Python-запускатель задаёт PYTHONUNBUFFERED и через exec заменяет себя процессом sqlmap с тем же PID. Backend использует документированный `child_process.spawn` Caido без shell и передаёт аргументы массивом.

## Настройка

- Исполняемый файл: по умолчанию `/usr/bin/sqlmap` на машине backend Caido.
- Для исходников sqlmap: исполняемый файл `/usr/bin/python3`, поле скрипта `/путь/sqlmap.py`.
- Два процесса одновременно, очередь до 20 задач, таймаут 600 секунд. Настройки доступны в интерфейсе.
- Перед запуском настрой Scope проекта: backend проверяет его при отправке задания и перед запуском.
- Параметры: необязательный список `-p`, например `id,search`.
- Базовый профиль: level 1 / risk 1 / boolean и error-based. Второй профиль повышает level до 2 для cookies. GET и поддерживаемые тела разбирает sqlmap. Уже имеющиеся маркеры `*` в исходном запросе передаются без изменения; автоматическая расстановка маркеров пути/заголовков в этой версии не реализована.

Установка, открытие страницы и выбор запроса не запускают проверки. Нет пассивного автосканирования трафика. Все настройки запускаются пользователем кнопками «Запустить» или «Повторить».

## Задачи, журнал и результаты

Показываются задачи текущего проекта, состояния, PID, ошибки и последние 200000 символов журнала. «Стоп» отменяет ожидающее задание или отправляет SIGTERM работающему процессу, затем SIGKILL через 3 секунды, если он не завершился. Длительные задачи ограничены таймаутом. SQLmap запускается напрямую, а не через промежуточную оболочку.

Каждая задача хранит исходный запрос, журнал и sqlmap output в `sdk.meta.path()/sqlmap-manager/<task-id>/`. В интерфейсе отображается абсолютный путь. Каталоги создаются с режимом 0700, файлы с 0600. Запросы могут содержать cookies и авторизацию. Основной журнал ограничен 5 млн символов; собственные файлы sqlmap и история задач сохраняются до ручного удаления.

Активный дубликат того же request ID и профиля возвращает существующее задание. Завершённые задачи можно запускать повторно без удаления Findings.

Findings создаются после распознавания итоговой сводки sqlmap с Parameter, Type и Payload. Сообщения о возможной инъекции и код завершения 0 сами по себе не создают Finding. Finding помечен «SQLmap reported» и содержит доказательство для ручной оценки. Парсер англоязычного текстового вывода может пропустить результат при изменении формата sqlmap. Процент выполнения не вычисляется; отображается состояние и живой журнал.

Если проект переключён до запуска, задача завершится ошибкой. Уже работающий процесс может закончить работу; результат не публикуется в другой проект. При возвращении на страницу плагина в исходном проекте отложенная публикация Findings повторяется.

После перезапуска плагина незавершённые задания помечаются interrupted и автоматически не возобновляются. Удалённый/отключённый плагин не гарантирует остановку уже запущенного процесса: перед отключением используй «Стоп». После аварийного завершения проверь записанный PID вручную; плагин не посылает сигнал старому PID автоматически.

## Сборка

`python3 build.py` создаёт ZIP из исходных JS/CSS и manifest. Зависимости npm не требуются. Это только упаковка файлов: код плагина и sqlmap не исполняются.

По просьбе пользователя плагин, сканирование и тесты не запускались. Импорт и совместимость с установленной версией Caido пока не проверены.

Использованная документация: https://developer.caido.io/plugins/concepts/child_process.html, https://developer.caido.io/plugins/reference/manifest.html и определения SDK из https://github.com/caido/doc-developer .


## Версия 0.2.0

Вывод stdout/stderr подключён к журналу; Python-буферизация отключена через PYTHONUNBUFFERED=1. Добавлены PID, время последнего вывода, ошибки потоков и код завершения. Требуется Python (по умолчанию /usr/bin/python3); путь доступен в настройках. Работа этой правки в установленном Caido пока не проверялась.

Раздел «Кандидаты из Findings» читает Findings текущего проекта через GraphQL. Фильтр по части reporter или заголовка — `owasp` по умолчанию. Изменённый фильтр сохраняется кнопкой настроек. Список обновляется примерно раз в 8 секунд, пока открыта страница. На странице читаются 100 Findings всех источников; «Загрузить более старые» продолжает пагинацию. Ранее загруженные кандидаты остаются до полного обновления кнопкой. Перед запуском Finding повторно запрашивается по ID.

«Выбрать» переносит request ID в форму настройки. «Запустить базовый» вручную отправляет исходный запрос на проверку. Импорт Findings ничего не сканирует. Scope проверяется при отправке и запуске. Собственные Findings SQLmap Manager не импортируются. Имена параметров не считаются доказательством SQLi.

Плагин, тесты и sqlmap при подготовке обновления не запускались; выполнена только упаковка файлов.


## Версия 0.2.2

Добавлен --ignore-stdin: sqlmap использует файл запроса, а не пустой stdin процесса Caido. В установленном исходнике sqlmap подтверждено, что не-TTY stdin включает режим списка целей без этого флага. fs.appendFile заменён на fs.writeFile с ограниченным буфером и периодической записью; финальная запись выполняется перед завершением задачи. Журнал можно выделять и копировать кнопкой; обновление не сбрасывает выделенный текст. Код и архив обновлены без запуска плагина, sqlmap или тестов.
