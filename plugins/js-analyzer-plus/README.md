JS Analyzer Plus разбирает JavaScript из перехваченных ответов и помогает найти интересные места приложения: скрытые маршруты, API endpoints, секреты, тестовые учётные данные и обращения к cookies.

Плагин объединяет [Community JS Analyzer](https://github.com/caido-community/JS-Analyzer) с нашим AST-анализатором на Acorn. От исходного проекта сохранены интерфейс просмотра ответов, 12 анализаторов, подсветка совпадений и экспорт. Добавлены восстановление вложенных маршрутов, разбор строк в обратных кавычках, связанные login/password и компактные Findings.

## Установка

1. Собери `dist/plugin_package.zip` по [инструкции ниже](#сборка).
2. Импортируй архив в Caido через **Plugins → Install**.
3. Пропусти трафик браузера через Caido и открой сайт.
4. Смотри результаты в **Findings** с reporter **JS Analyzer Plus**.

На новой установке автоскан включён. При обновлении сохраняется прежняя настройка. Переключить её можно через палитру команд:

```text
JS Analyzer Plus: Toggle automatic passive scan
```

После переключения появится уведомление `enabled` или `disabled`. Если установлены исходный JS Analyzer или старый JS Source Analyzer, их можно отключить, чтобы не получать параллельный анализ.

## Режимы работы

| Действие | Что происходит | Запись в Findings |
| :--- | :--- | :--- |
| Открыть сайт через Caido | Автоматический анализ новых подходящих ответов | Только отобранные категории, с группировкой |
| Запустить скан из контекстного меню | Полный анализ выбранных сохранённых ответов | **Нет автоматической записи** |
| Открыть `JS Analysis Plus` в просмотре ответа | Анализ содержимого ответа | Нет автоматической записи |
| Нажать отправку в Findings в окне результатов | Сохранение выбранной находки или группы | Только по явному действию |

> **Скан по кнопке не выгружает весь результат в Findings.** Энтропия, DOM sinks и остальные эвристики остаются в окне анализа, пока ты сам не отправишь их.

### Пассивный автоскан

Работает на backend: открывать вкладку плагина для этого не нужно. Анализируются новые ответы, которые проходят через Caido: JavaScript, JSON и файлы с расширениями `.js`, `.mjs`, `.cjs`, `.json`, `.map`. JavaScript определяется также по Content-Type, даже если в URL нет расширения.

Автоматически в Findings попадают:

- **Маршруты и API endpoints** — в том числе вложенные AST-маршруты и Angular hash routes.
- **Секреты и захардкоженные значения** — по именам полей и конкретным шаблонам, без находок только по высокой энтропии.
- **Связанные login/password** — одной записью, когда связь однозначна.
- **Email, внутренние IP и служебные endpoints.**
- **Именованные операции с cookies** — чтение, запись и другие распознанные обращения.

Общие вызовы функций, DOM sinks, признаки фреймворков, чанки, source maps, облачные адреса, поддомены и кандидаты dependency confusion доступны в полном ручном анализе. Они не публикуются автоматически.

### Полный анализ по кнопке

В **HTTP History** выдели один или несколько запросов и выбери:

```text
Run JS Analyzer Plus - Passive scan
```

Откроется окно результатов: категории, совпадения, исходный ответ и действия копирования, экспорта и отправки в Findings. Поддерживается экспорт в **JSON** и **CSV**.

Название команды содержит `Passive scan`, потому что анализируется содержимое ответа. Сам запуск выполняется вручную. Обнаруженные маршруты плагин не запрашивает и в Sitemap не добавляет.

## Примеры Findings

Примеры ниже иллюстрируют содержимое находок; это не скриншоты интерфейса.

### API endpoints — одна запись вместо сотен

**JS Analyzer Plus: API endpoints — 3 endpoints**

**Source:** `https://example.test/main.js`

**API endpoints: 3**

- `/api/users`
- `/rest/products/search`
- `/rest/user/login`

Пути сортируются, повторы AST- и regex-анализаторов объединяются. В описание попадает весь обнаруженный список без обрезания. Для AST-маршрутов действует та же схема: одна запись на URL исходника и тип маршрутов, например `Angular hash route`.

### Login и password — вместе, со значениями

Для такого кода:

```js
class LoginComponent {
  testingUsername = `testing@juice-sh.op`;
  testingPassword = `IamUsedForTesting`;
}
```

Finding будет выглядеть так:

**JS Analyzer Plus: Hardcoded login and password**

- **Login** (`testingUsername`): `testing@juice-sh.op`
- **Password** (`testingPassword`): **`IamUsedForTesting`**

В реальном выводе рядом указаны строка и позиция значения в исходнике. Пароль показывается целиком и выделяется жирным.

Поля объединяются, только если в одном блоке или объекте, у одного получателя и с одинаковым префиксом имени найдены ровно один логин и один пароль. Поля из разных объектов и функций, а также неоднозначные сочетания остаются отдельными кандидатами. Динамические значения не вычисляются.

### Cookies, email и внутренние адреса — списками

Операции с cookies одного JS-файла собираются в одну Finding, например:

- `get continueCode`
- `set sessionMode`
- `write role`

Отдельными списками группируются email и внутренние IP. При явной отправке из полного анализа группируются также поддомены. Обнаруженное обращение к cookie помогает найти соответствующий код, но само по себе не подтверждает возможность обхода авторизации.

### Повторы и обновления

Повторный ответ с теми же находками не создаёт их заново. Дедупликация учитывает URL исходника, категорию и значение; для списков используется отсортированный набор элементов.

Если URL или список изменился, может появиться новая сводка. Старые Findings не переписываются и не удаляются — в том числе после обновления плагина с версий, которые создавали отдельные записи на каждый маршрут.

## Настройки

Кроме команды переключения автоскана, backend хранит следующие параметры. Отдельной страницы настроек для них сейчас нет.

| Параметр | По умолчанию | Назначение |
| :--- | :--- | :--- |
| `autoScanEnabled` | `true` | Автоматический анализ новых ответов |
| `inScopeOnly` | `false` | Ограничение автоскана Scope проекта |
| `enabledAnalyzers` | Все анализаторы | Набор анализаторов автоскана; затем применяется отбор Findings |
| `allowNetworkRequests` | `false` | Разрешение проверки npm-пакетов в ручном анализе dependency confusion |

Пассивный автоскан не отправляет дополнительных запросов, включая проверки npm. Ручной запуск из меню использует все анализаторы.

## Сборка

Нужны **Node.js**, **pnpm** и **Python 3**. Выполни из корня репозитория:

```bash
cd plugins/js-analyzer-plus
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build
```

Готовый архив:

```text
plugins/js-analyzer-plus/dist/plugin_package.zip
```

Архив содержит backend, frontend, manifest и лицензии. JavaScript стороннего приложения при анализе не выполняется.

## Границы анализа

- Находки — статические кандидаты. Маршрут может быть клиентским, ключ — тестовым, а найденный пароль — уже неиспользуемым.
- Пустые ответы и ответы больше 6 MiB символов пропускаются автосканом. AST-разбор ограничен глубиной 300 и 200 результатами на категорию.
- Если Acorn не разбирает синтаксис, остаются regex-анализаторы; полнота восстановления маршрутов и пар учётных данных снижается.
- Не обещается полное восстановление серверных маршрутов, динамических базовых путей или Next.js App Router.
- Минификация имён может скрыть обращения к cookie-сервисам. Значения, вычисляемые во время выполнения, не восстанавливаются.
- Findings и экспорт могут содержать открытые пароли и токены: это фактические значения из исследуемого ответа.
